# Belgian eID — Windows Installer

[![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-0078D4?style=flat-square&logo=windows)](https://eid.belgium.be)
[![Inno Setup](https://img.shields.io/badge/Inno%20Setup-6-lightgrey?style=flat-square)](https://jrsoftware.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg?style=flat-square)](../LICENSE)

Single-command Windows installer that bundles the [bridge](../bridge/README.md) and the [Chrome extension](../extension/README.md) into a single `.exe`. Installs silently for end users — no developer mode, no manual registry editing.

---

## What the installer does

1. Copies `BelgianEidBridge.exe` (self-contained .NET 8) to `%ProgramFiles%\BelgianEid\bridge\`
2. Copies `BelgianEid.crx` to `%ProgramFiles%\BelgianEid\extension\`
3. Writes the Native Messaging host manifest (`be.belgianeid.bridge.json`) to `bridge\`
4. Writes an `update.xml` sideload manifest alongside the `.crx`
5. Registers the Native Messaging host in `HKLM\SOFTWARE\Google\Chrome\NativeMessagingHosts\`
6. Force-installs the extension via Chrome Group Policy (`ExtensionInstallForcelist`)

No reboot required. Chrome must be restarted once after installation.

## Structure

```
installer/
├── build.ps1              Build pipeline (bridge → crx → installer)
├── setup.iss              Inno Setup 6 script (do not run directly)
├── extension-key.pem      Chrome signing key — gitignored, store in a secrets manager
├── artifacts/             Generated by build.ps1 — gitignored
│   ├── bridge/            Self-contained bridge publish output
│   ├── extension/
│   │   └── BelgianEid.crx
│   ├── extension-id.txt   32-char stable extension ID
│   └── installer-config.iss  #define AppVersion / ExtensionId — auto-generated
└── output/                Final installer EXE — gitignored
    └── BelgianEidSetup-x.x.x.exe
```

> **`extension-key.pem` is critical.** Losing it changes the extension ID on already-deployed machines — Chrome will treat the new ID as a different extension and users will lose the installed extension. Store it in a secrets manager (KeePass, Bitwarden, or a CI secret store). It is excluded from git via `.gitignore`.

## Build

Run from the repository root or from the `installer/` directory:

```powershell
cd installer
.\build.ps1
```

On first run, Chrome generates `extension-key.pem` and prompts you to close any open Chrome windows. Subsequent runs reuse the existing key — the extension ID stays stable.

### Build parameters

| Parameter | Description |
|---|---|
| `-SkipBridge` | Skip `dotnet publish` — reuse existing `artifacts/bridge/` |
| `-SkipExtension` | Skip Chrome packaging — reuse existing `artifacts/extension/BelgianEid.crx` |
| `-SkipInstaller` | Skip Inno Setup compilation — useful to inspect artifacts only |
| `-IsccPath <path>` | Explicit path to `iscc.exe` if auto-detection fails |

```powershell
# Recompile only the installer (bridge and extension already built)
.\build.ps1 -SkipBridge -SkipExtension

# Build bridge and extension but stop before Inno Setup
.\build.ps1 -SkipInstaller

# Specify a custom Inno Setup path
.\build.ps1 -IsccPath "D:\Tools\InnoSetup6\iscc.exe"
```

### Output

```
installer/output/BelgianEidSetup-x.x.x.exe
```

The version number is read from `extension/manifest.json` (`"version"` field).

## Build pipeline — step by step

```
build.ps1
  │
  ├── [1/4] dotnet publish bridge/BelgianEidBridge.csproj
  │         --runtime win-x64 --self-contained
  │         → artifacts/bridge/
  │
  ├── [2/4] chrome --pack-extension=extension/
  │         → artifacts/extension/BelgianEid.crx
  │         → installer/extension-key.pem  (first run only)
  │         Updates extension/manifest.json "key" field
  │         Updates bridge/be.belgianeid.bridge.json "allowed_origins"
  │
  ├── [3/4] Generate artifacts/installer-config.iss
  │         #define AppVersion  "x.x.x"
  │         #define ExtensionId "abcdef..."
  │
  └── [4/4] iscc setup.iss
            → output/BelgianEidSetup-x.x.x.exe
```

## Inno Setup script (`setup.iss`)

`setup.iss` must not be compiled directly — it `#include`s `artifacts/installer-config.iss` which is generated by `build.ps1`. Running `iscc setup.iss` without that file will fail.

Key installer behaviors defined in `setup.iss`:

| Behavior | Detail |
|---|---|
| Install location | `%ProgramFiles%\BelgianEid\` |
| Privileges | Administrator required |
| Architecture | 64-bit only (`x64compatible`) |
| Minimum Windows | 10.0.17763 (1809) |
| Native Messaging host | Written at post-install via Pascal script |
| Extension force-install | Chrome Group Policy `ExtensionInstallForcelist` via `file://` sideload URL |
| Uninstall | Removes registry keys (`uninsdeletekey`, `uninsdeletevalue`) |

## Bumping the version

The installer version is driven entirely by the `"version"` field in `extension/manifest.json`. Update that field, then rebuild:

```powershell
# In extension/manifest.json
{ "version": "1.2.0", ... }

# Then
cd installer
.\build.ps1
# Output: output/BelgianEidSetup-1.2.0.exe
```
